# Reverse proxy Caddy avec HTTPS automatique

Caddy est un serveur web qui obtient et renouvelle **tout seul** tes certificats TLS (Let's Encrypt). Tu déclares un domaine, il s'occupe du HTTPS. Renseigne ta config à gauche : les commandes se remplissent avec tes valeurs.

<Diagram name="caddy-https" />

<Automatic>

```bash
# Installe Caddy, écrit un Caddyfile minimal et recharge — tout d'un coup.
sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt update && sudo apt install -y caddy
printf '%s {\n    reverse_proxy 127.0.0.1:8080\n}\n' "${DOMAIN}" | sudo tee /etc/caddy/Caddyfile
sudo systemctl reload caddy
```

</Automatic>

## 00 — Le principe

<Detailed>Caddy écoute en 80/443, termine le TLS, et transmet les requêtes à ton application qui tourne en local (souvent sur un port comme 8080).</Detailed>

<Full>Contrairement à Nginx + Certbot où tu configures le proxy d'un côté et les certificats de l'autre, Caddy fait les deux : dès qu'un nom de domaine apparaît dans le Caddyfile, il déclenche l'obtention du certificat et le renouvellement automatique. Zéro cron, zéro fichier de conf TLS.</Full>

## 01 — Installer Caddy

<Detailed>On ajoute le dépôt officiel Caddy puis on l'installe via apt.</Detailed>

```bash
sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https curl
```

```bash
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt update && sudo apt install -y caddy
```

<Check id="caddy-installed" cmd="caddy version" expect="v2." />

## 02 — Écrire le Caddyfile

<Detailed>Le fichier `/etc/caddy/Caddyfile` décrit quel domaine pointe vers quelle app locale.</Detailed>

<Full>Remplace `127.0.0.1:8080` par l'adresse réelle de ton service (un conteneur Docker, un process Node, etc.). Tu peux empiler plusieurs blocs de domaines dans le même fichier.</Full>

```caddy
${DOMAIN} {
    reverse_proxy 127.0.0.1:8080
}
```

<Warn>Pour que Caddy obtienne le certificat, <V name="DOMAIN" /> doit déjà pointer (enregistrement DNS A) vers l'IP du serveur, et les ports 80 et 443 doivent être ouverts.</Warn>

## 03 — Recharger et vérifier

<Detailed>On recharge Caddy : il lit le Caddyfile et déclenche l'obtention du certificat.</Detailed>

```bash
sudo systemctl reload caddy
```

<Check id="caddy-https" cmd="curl -sI https://${DOMAIN} | head -n1" expect="HTTP/2 200" />

<Note>Le premier chargement peut prendre quelques secondes, le temps que Caddy négocie le certificat avec Let's Encrypt. Suis les logs avec `journalctl -u caddy -f` en cas de souci.</Note>

## 04 — Vérification finale

<Full>Si la commande renvoie `HTTP/2 200` et que ton navigateur affiche le cadenas, Caddy gère ton HTTPS de bout en bout, renouvellement compris.</Full>

<Check id="caddy-running" cmd="systemctl is-active caddy" expect="active" />
