# Runbook — Droplet sécurisé + Caddy + Portainer + TREK

Repartir de zéro : nouveau droplet DigitalOcean, config sécurisée, Caddy (auto-TLS), Portainer (GUI Docker exposée sur internet), puis TREK déployé comme première stack **via la GUI Portainer**.

<Diagram name="droplet-trek" />

<Detailed>Tous les conteneurs partagent un réseau Docker « edge ». Aucun port applicatif (3000, 9000…) n'est exposé directement : tout passe par Caddy en 80/443.</Detailed>

<Note>Décisions : Caddy auto-TLS · Portainer public maintenant, **filtre VPN en phase 2** (§8) · TREK déployé en stack depuis la GUI Portainer.</Note>

## 1. Créer le droplet

- **Image** : Debian 13 (x64).
- **Taille** : Basic 2 vCPU / 2 Go RAM / 50 Go (1 Go RAM minimum).
- **Région** : proche de toi.
- **Auth** : clé SSH.
- **Hostname** : <V name="HOSTNAME" />.

<Detailed>Caddy + Portainer + TREK restent légers. Prends un droplet **neuf et dédié** (pas le droplet VPN), et note son IP publique — c'est elle que tu renseignes dans la config à gauche : <V name="SERVER_IP" />.</Detailed>

## 2. DNS (zone <V name="DOMAIN" />)

Deux enregistrements A vers le même droplet :

```text
portainer   A   ${SERVER_IP}   (TTL 300)
travel      A   ${SERVER_IP}   (TTL 300)
```

<Detailed>Vérifie la propagation **avant** de lancer Caddy, sinon l'émission des certificats Let's Encrypt échoue.</Detailed>

<Check id="dt-dns" cmd="dig +short portainer.${DOMAIN}" expect="${SERVER_IP}" />

## 3. Durcissement du serveur

<Detailed>À faire connecté en `root` sur une Debian 13 fraîche. On installe les paquets de base (souvent absents de l'image minimale DO), on crée un utilisateur non-root avec ta clé, on ferme le pare-feu, on active les mises à jour de sécurité.</Detailed>

```bash
ssh root@${SERVER_IP}
apt update && apt -y upgrade
apt -y install sudo curl ca-certificates gnupg ufw unattended-upgrades fail2ban
# Utilisateur non-root
adduser ${USERNAME}
usermod -aG sudo ${USERNAME}
# Copier ta clé SSH vers le nouvel utilisateur
mkdir -p /home/${USERNAME}/.ssh
cp ~/.ssh/authorized_keys /home/${USERNAME}/.ssh/
chown -R ${USERNAME}:${USERNAME} /home/${USERNAME}/.ssh
chmod 700 /home/${USERNAME}/.ssh && chmod 600 /home/${USERNAME}/.ssh/authorized_keys
# Pare-feu : SSH + HTTP + HTTPS seulement
ufw allow 22/tcp
ufw allow 80/tcp
ufw allow 443/tcp
ufw --force enable
# Mises à jour de sécurité automatiques
dpkg-reconfigure -plow unattended-upgrades
```

Durcir SSH dans `/etc/ssh/sshd_config` :

```ini
PermitRootLogin no
PasswordAuthentication no
```

```bash
systemctl restart ssh
# Si Debian 13 active SSH par socket : systemctl restart ssh.socket
```

<Warn>Avant de fermer la session root, **ouvre un nouveau terminal et teste** la connexion `${USERNAME}`. Ne ferme root que si elle fonctionne, sinon tu te verrouilles dehors.</Warn>

<Check id="dt-ssh" cmd="ssh ${USERNAME}@${SERVER_IP} whoami" expect="${USERNAME}" />

<Note>`fail2ban` est déjà installé ci-dessus : il protège SSH du brute-force, actif par défaut.</Note>

## 4. Installer Docker

<Detailed>Connecté en `${USERNAME}`. Le script officiel gère Debian 13 et ajoute le dépôt Docker + `docker compose` v2.</Detailed>

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker ${USERNAME}
# se déconnecter / reconnecter (ou: newgrp docker) pour activer le groupe docker
docker --version && docker compose version
```

<Check id="dt-docker" cmd="docker compose version" expect="Docker Compose version v5.2.0" />

## 5. Bootstrap : réseau + Caddy + Portainer (CLI)

<Detailed>Ces deux services d'infra se lancent une fois en CLI ; ensuite tout (dont TREK) se gère via la GUI Portainer.</Detailed>

```bash
# Réseau partagé que TREK rejoindra plus tard
docker network create edge
mkdir -p ~/infra && cd ~/infra
```

`~/infra/Caddyfile` :

```caddy
portainer.${DOMAIN} {
    reverse_proxy portainer:9000
}
travel.${DOMAIN} {
    reverse_proxy trek:3000
}
```

<Note>Caddy gère TLS **et** les WebSockets automatiquement (TREK en a besoin pour la sync temps réel). Le host `travel` renverra une erreur tant que TREK n'est pas déployé (§7) — c'est normal.</Note>

`~/infra/docker-compose.yml` :

```yaml
services:
  caddy:
    image: caddy:2-alpine
    container_name: caddy
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    networks: [edge]
  portainer:
    image: portainer/portainer-ce:latest
    container_name: portainer
    restart: unless-stopped
    # Pas de "ports:" — Portainer n'est joignable QUE via Caddy
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
      - portainer_data:/data
    networks: [edge]
networks:
  edge:
    external: true
volumes:
  caddy_data:
  caddy_config:
  portainer_data:
```

```bash
docker compose up -d
docker compose logs -f caddy   # vérifier l'émission des certificats
```

<Check id="dt-caddy" cmd="docker compose ps" expect="caddy   running" />

## 6. Premier accès Portainer (sécurisation)

1. Ouvrir `https://portainer.${DOMAIN}` (TLS déjà actif via Caddy).
2. Créer l'utilisateur admin avec un **mot de passe fort**.
3. Choisir l'environnement **local** (socket Docker déjà monté).
4. **Activer la 2FA** : *My account ▸ Two-factor authentication* (TOTP).
5. *Settings* : sessions courtes, désactiver l'auto-update non voulu.

<Warn>Portainer verrouille la création de l'admin après quelques minutes. Si tu rates la fenêtre : `docker restart portainer`. Le panneau étant exposé sur internet, la 2FA est **indispensable**.</Warn>

<Check id="dt-portainer" cmd="curl -sI https://portainer.${DOMAIN} | head -n1" expect="HTTP/2 200" />

## 7. Déployer TREK via la GUI Portainer

<Detailed>Dans Portainer : **Stacks ▸ Add stack**, nom `trek`, méthode *Web editor*, coller la stack ci-dessous. Pas de `ports:` — TREK n'est exposé que via Caddy sur `travel.${DOMAIN}`.</Detailed>

```yaml
services:
  trek:
    image: mauriceboe/trek:latest
    container_name: trek
    restart: unless-stopped
    read_only: true
    security_opt:
      - no-new-privileges:true
    cap_drop: [ALL]
    cap_add: [CHOWN, SETUID, SETGID]
    tmpfs:
      - /tmp:noexec,nosuid,size=64m
    environment:
      - NODE_ENV=production
      - PORT=3000
      - ENCRYPTION_KEY=${ENCRYPTION_KEY}
      - APP_URL=https://travel.${DOMAIN}
      - ALLOWED_ORIGINS=https://travel.${DOMAIN}
      - FORCE_HTTPS=true
      - TRUST_PROXY=1
      - TZ=Europe/Paris
      - ADMIN_EMAIL=${EMAIL}
      - ADMIN_PASSWORD=change-me-fort
    volumes:
      - trek_data:/app/data
      - trek_uploads:/app/uploads
    networks: [edge]
    healthcheck:
      test: ["CMD", "wget", "-qO-", "http://localhost:3000/api/health"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 15s
networks:
  edge:
    external: true
volumes:
  trek_data:
  trek_uploads:
```

<Detailed>Avant de déployer, dans la section **Environment variables** de Portainer, ajoute `ENCRYPTION_KEY`. Génère-la une fois, et **conserve-la précieusement** — sans elle les secrets chiffrés sont irrécupérables.</Detailed>

```bash
openssl rand -hex 32
```

<Note>Clique **Deploy the stack**. Caddy route déjà `travel.${DOMAIN}` → `trek:3000`. Ouvre l'app, connecte-toi avec l'admin, et teste la sync temps réel sur deux onglets.</Note>

<Check id="dt-trek" cmd="curl -I https://travel.${DOMAIN}" expect="HTTP/2 200" />

## 8. Phase 2 — Filtrer Portainer derrière le VPN

<Warn>À faire plus tard, quand l'IP/subnet du VPN sera décidé. Tant que ce filtre n'est pas en place, Portainer reste **public** : mot de passe fort + 2FA obligatoires.</Warn>

```caddy
portainer.${DOMAIN} {
    @vpn remote_ip VPN_IP_OU_SUBNET     # ex. 203.0.113.10  ou  10.8.0.0/24
    handle @vpn {
        reverse_proxy portainer:9000
    }
    respond "Forbidden" 403
}
```

```bash
docker exec -w /etc/caddy caddy caddy reload
```

## 9. Maintenance

- **Mettre à jour un conteneur** : depuis Portainer (Recreate + pull image), ou en CLI `docker compose pull && docker compose up -d` dans `~/infra` pour Caddy/Portainer.
- **Backups TREK** : activer les auto-backups dans le panneau Admin de TREK ; données dans les volumes `trek_data` / `trek_uploads`. Envisager un push hors-site.
- **Caddy** : les certificats se renouvellent tout seuls (volume `caddy_data`).

## Récap des décisions

- **Droplet** : neuf, dédié (<V name="HOSTNAME" />).
- **Reverse proxy / TLS** : Caddy (auto Let's Encrypt).
- **Gestion conteneurs** : Portainer CE, GUI sur `portainer.${DOMAIN}`.
- **Exposition Portainer** : public + mot de passe fort + 2FA ; filtre VPN en phase 2.
- **TREK** : stack déployée via la GUI Portainer, sur `travel.${DOMAIN}`.
- **Ports** : aucun port applicatif direct ; tout via Caddy (80/443).
